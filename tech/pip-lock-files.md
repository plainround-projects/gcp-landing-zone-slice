# pip, virtual environments, hash-pinned lock files and pip-audit

## 1. What it is

`pip` installs Python libraries. A **virtual environment** (`python -m venv .venv`) is a private folder with its own Python and its own installed libraries. A **lock file** lists every library the project needs — including the libraries those libraries need — each with an exact version and a **hash** (a fingerprint of the downloaded file). `uv` is a fast tool that can generate such a file from `pyproject.toml`. `pip-audit` checks a list of exact versions against a database of known security vulnerabilities.

## 2. Why this repository uses it

The repository must be reproducible and safe: the same versions everywhere (laptop, CI and anywhere else it runs), and a download that was tampered with must be refused. Hash pinning gives both; `pip-audit` runs on every push.

## 3. Where it appears

| Path | What it does |
| --- | --- |
| `requirements.lock` | Run-time libraries with versions and hashes. It holds PyYAML, the one run-time library, and nothing else. |
| `requirements-dev.lock` | Run-time plus development tools, with hashes. |
| `Makefile` | `make install` creates `.venv` and installs from `requirements-dev.lock`; `make audit` runs `pip-audit`. |
| `.github/workflows/ci.yml` | Runs the same install and the audit. |


## 4. How it works underneath

`pip install -r file` installs what a file lists. A **transitive dependency** is a library needed by a library you asked for; the lock file lists these too. With `--require-hashes`, pip checks each downloaded file against its `--hash=sha256:...` entries and refuses a mismatch (and refuses any package with no hash). The lock file is generated with:

```text
uv pip compile pyproject.toml --extra dev --generate-hashes --python-version 3.12 -o requirements-dev.lock
```

(`--extra dev` includes the development group; the run-time lock is the same command without it.) `pip-audit -r requirements-dev.lock --no-deps --disable-pip` looks up each pinned `name==version` in a vulnerability database; `--no-deps` says the file is already complete, `--disable-pip` stops it from creating its own environment.

## 5. Walkthrough of this repository's use

`Makefile`

```make
$(STAMP): requirements-dev.lock pyproject.toml
	$(PYTHON) -m venv $(VENV)
	$(VENV)/bin/pip install -q --require-hashes -r requirements-dev.lock
	$(VENV)/bin/pip install -q --no-deps -e .
	touch $@
```

- `$(PYTHON) -m venv $(VENV)` creates `.venv`.
- `pip install -q --require-hashes -r requirements-dev.lock`: quiet install, refusing anything without a matching hash.
- `pip install -q --no-deps -e .`: install this project in editable mode; its dependencies are already installed, so `--no-deps` stops pip from looking again.

The shape of the lock file:

`requirements-dev.lock`

```text
# This file was autogenerated by uv via the following command:
#    uv pip compile pyproject.toml --extra dev --generate-hashes --python-version 3.12 -o requirements-dev.lock
ast-serialize==0.13.1 \
    --hash=sha256:02686b281ec9b8e9614f6f0db27e12e4cac515f336c5d05b678bc9eb73ff2af5 \
```

Each package is a line `name==version \` followed by one or more `--hash` lines. The comment `# via ...` under a package says which package pulled it in.

`Makefile`

```make
audit: $(STAMP) ## check the locked dependencies for known vulnerabilities
	$(VENV)/bin/pip-audit --no-deps --disable-pip -r requirements-dev.lock
```

## 6. Try it yourself

```bash
head -12 requirements-dev.lock
```
Expected: the "autogenerated" header and the first packages with hashes.

```bash
grep -c "^[a-z0-9_.-]*==" requirements-dev.lock
```
Expected: the number of pinned packages (a few dozen to a few hundred).

```bash
.venv/bin/pip list 2>/dev/null | head -5
```
Expected: a table of installed packages, including this project.

```bash
make audit
```
Expected: `No known vulnerabilities found` (needs network access to the vulnerability database).

## 7. Mistakes people make

- **Installing with plain `pip install package`** and getting a different version later. The lock file prevents it.
- **Skipping hashes.** A swapped file would install silently.
- **Editing the lock file by hand.** Regenerate it.
- **Forgetting the audit.** New vulnerabilities appear after you pin; the audit runs on every push.
- **Using the system Python.** Always use `.venv`.

## 8. Check yourself

1. What is a transitive dependency? *A library needed by one of your libraries.*
2. What does `--require-hashes` do? *Makes pip verify every download against the listed hash.*
3. Why `--no-deps` for the project install? *The lock file already installed everything.*
4. What is a virtual environment for? *A private set of libraries per project.*
5. What does `pip-audit` compare against? *A database of known vulnerabilities, using the pinned versions.*
